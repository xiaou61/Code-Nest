# 项目常驻规范

本文件保存跨工作项长期有效、且已由用户确认的事实与约束。当前是草案，未确认项统一标注「待项目确认」；用户确认后把 frontmatter 的 `status` 改为 `active`、`configured` 改为 `true`，并删掉本段。

## 项目定位

Paideia 是「千人千面的 AI 个性化学习平台」。目标不是把同一套课程分发给所有人，而是让每个学习者拥有自适应的学习路径、内容与反馈。

## 项目常驻约束（MUST）

- 进入实现、部署、迁移或数据变更前必须确认本文件；未确认项不得按猜测执行。
- 技术栈（2026-10-09 由用户指定）：
  - 后端：Spring Boot 4 + JDK 25（Boot 当前 4.1.1；starter 已改名，`spring-boot-starter-web` → `spring-boot-starter-webmvc`；Undertow 已移除）。
  - 数据访问：**手写 MyBatis，禁止引入 MyBatis-Plus**（当前 3.5.19，无 3.6.x GA）。
  - 数据库：MySQL 起步，但**必须保留多数据库适配能力**。
  - 前端：React 最新稳定版（当前 19.3，无 React 20）。
  - 不得使用 JDK 预览特性（结构化并发等在 JDK 25 仍是预览）。
- 持久层可移植纪律（在 `databaseId` 机制上叠加）：
  - 主键一律应用侧生成（Snowflake 或 UUIDv7），不用数据库自增/序列取值。
  - 分页必须由方言抽象产生，禁止 `RowBounds`。
  - 基础语句不得包含 `upsert`、`SKIP LOCKED`、`MERGE`、`RETURNING`、JSON 算子等不可移植语法；方言差异只允许以 `databaseId` 分支出现。
  - 标识符统一小写 snake_case，避免保留字；时间统一存 UTC。
  - 启动时必须输出实际解析到的数据库方言，方言匹配失败不得静默。
- 架构形态与模块边界规则：待项目确认（WORK-001 结论）。
- 仓库结构、构建与检查命令：待项目确认（仓库当前为空）。
- 部署目标与形态：待项目确认。
- 涉及学习者个人数据的功能，必须先明确数据隔离、留存与隐私要求，再进入设计。
- 本地提交需用户明确授权；`git push`、远端分支、tag、部署必须单独授权。
- 凭据、密钥、令牌不得写入源码、项目工件或更新历史。
- 元规则：若项目代码出现与本节同等长期有效的规则变更，更新本文件而不是只写进单个工作项。
