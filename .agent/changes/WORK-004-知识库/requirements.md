# 知识库需求

本工件由 2026-10-10 的连续讨论整理而成。讨论中的原始范围较大，经用户同意按文末「拆分后的后续工作项」一节拆成四块，本项只承载第一块。

## 已确认事实

### 仓库现状（读源码与迁移确认，2026-10-10）

- 后端 6 个 Maven 模块：`paideia-platform`（契约）、`paideia-web`、`paideia-persistence`、`paideia-security`、`paideia-account`、`paideia-app`。**计划中的 `ai` 模块尚未创建。**
- Flyway 生产迁移**只有一个文件** `paideia-app/src/main/resources/db/migration/V1__create_account_tables.sql`；**项目至今没有任何内容类表**。生产迁移集中在 `paideia-app`，测试夹具在 `db/testdata`（V900+），开发与 e2e 种子在 `db/devdata`（任何 profile 默认都不加载）。
- 本项目**不使用 MyBatis XML**：mapper 是 `@Mapper` 注解接口 + Java 文本块写 SQL，自增主键用 `@Options(useGeneratedKeys = true, keyProperty = "id")`，因此实体是可变类而不是 record；分页手写 `LIMIT #{limit} OFFSET #{offset}` + 独立 count 语句。
- 前端四应用面：`apps/app`（学习者端，Web 与桌面共用产物）、`apps/admin`（仅 Web）、`apps/public`、`apps/ui-kit`；共享包 `@paideia/ui`、`@paideia/core`、`@paideia/auth` 已交付。
- **`apps/admin` 目前只有一屏且没有路由**：`main.tsx` 直接渲染 `AdminHomePage`，`apps/admin/package.json` 里没有 `react-router`；角色判定用 `src/guard.tsx` 的 `canEnterAdmin`（转调 core 的 `canAccessAdmin`）。
- 学习者端**整体要求登录**；管理端已有界面层守卫。管理员只能由种子迁移或运维手段产生。
- 当前用户身份只能取自 `io.github.xiaou61.security.CurrentUser.subjectId()` / `role()`，接口层不接受客户端传 userId。
- 内容检索的既有裁决是**用 MySQL 全文检索承担**（本期不做向量检索）。
- 服务器上**没有 Docker、没有对象存储服务**；自托管单实例。

### 关键缺口（读源码确认，本项必须补）

- **后端目前没有任何按角色限制的路径规则。** `SecurityConfiguration` 的过滤器链只放行 `/actuator/health`、`/error`、`/api/v1/auth/**`，其余一律 `anyRequest().authenticated()`；没有 `@EnableMethodSecurity`、没有 `@PreAuthorize`、没有任何 `.hasRole(...)` 的匹配器。角色目前只被 JWT 转换器映射成 `ROLE_ADMIN` / `ROLE_LEARNER` 权限，**从未被用来拒绝任何请求**。
  这意味着：本项的管理端写接口若不自带角色限制，**任何已登录的学习者都能写入知识库**。这是本项必须闭合的缺口，也是 AC-006 的来源。
- **`<img src>` 不会携带 `Authorization` 头**，而本项目是无状态 JWT、没有 Cookie（Cookie 在 D-10 因桌面壳来源非 http(s) 域被排除）。因此受保护的文件端点无法用最普通的 `<img>` 取到——这是"文件端点是否鉴权"这个决定的物理约束。
- `AccountApi` 目前**没有任何消费者**（全仓只有定义、实现与自身 mapper）。本项不需要账号数据，只取当前用户身份，因此不引入对 `paideia-account` 的依赖。

### 已裁决且本项必须遵守的既有决定

- 编码约定：SQL 只写在 mapper、时间存 UTC、标识符小写 snake_case、主键数据库自增；分页用 MySQL 分页组件。
- 模块边界由 Spring Modulith 在构建期强制；一个 Maven 模块一个模块；跨模块只能依赖对方包根的类型。
- 前端颜色只有 `globals.css` 一个来源；新增含 `.tsx` 的包必须同步登记 `@source`（有自动化检查）。
- `packages/ui` 不得引用 `@paideia/core`、`react-router` 或平台包（有自动化检查）。
- **公开仓库**：凭据、密钥、令牌、连接串、服务器地址一律不得写入任何被 Git 跟踪的文件；上传的二进制同样不进仓库。

### 联网核实（2026-10-10，为回答「能否以 Pi 为基准」而做）

- **Pi（pi.dev，Earendil Inc.，MIT）是 Node/TypeScript 写的终端 agent harness**，官方定位是在终端里工作的 agent，提供 interactive / print-JSON / RPC / TypeScript SDK 四种模式；RPC 走 stdin/stdout 供非 Node 集成，SDK 是 TypeScript；会话默认存本地磁盘文件；官方明列不内置 sub-agents、权限弹窗与 plan mode，且**不沙箱化工具调用**。
- **推论**：本项目后端是 Java，**Pi 无法作为库嵌入 Spring Boot**；可选形态只有「Java 侧子进程旁挂」或「仅覆盖桌面端」。用户已据此裁决**维持 AgentScope**（见「用户决定」第 7 条）。事实来源：`https://pi.dev/` 与 `https://pi.dev/docs`。

## 用户决定

以下均由用户在 2026-10-10 的讨论中逐条裁决。

1. **知识库的基准单元**：一张表，**一行一个知识条目**，正文是类 md 的内容。**它不是考题**——没有题型、没有选项、没有标准答案、不做判分。讨论中一度出现的「选择题／代码题／题型扩展」假设**已作废**。
2. **分类是层级树**。
3. **内容录入走管理端界面**（`apps/admin`）。学习者侧不写入。
4. **学习者侧只做「查看」**：浏览、打开、读。作答、判分、掌握度、学习路径**全部不在本版**。
5. **内容组织能力全要**：列表与详情、层级分类导航、检索、知识图谱可视化、管理端内容录入。
6. **本工作项接受拆分**：AI 助手、Agent 运行时、个人笔记各自另开工作项，本项只做知识库本体（见文末）。
7. **AI 框架维持 AgentScope**（否决了改以 Pi 为基准的方案）。
8. **对象存储现在就定，但只用本地**：本版支持图片与附件上传，存储用**服务器本地目录**，且这项能力必须收在一个**可扩展的存储端口之后**——将来换 S3／OSS／MinIO 只替换端口实现，不改业务代码。
9. **文件读取端点不鉴权**。用户明确裁决。理由与代价：`<img src>` 不带 `Authorization` 头，而不鉴权才能让图片直接可用并享受浏览器缓存；代价是**未发布条目里引用的图片，URL 一旦泄露就能被读到**（条目正文仍然受保护）。缓解是文件名用不可猜的 UUID 且不提供目录列举。

### 设计阶段由 Agent 收口的决定（用户授权「开始吧」时裁定，若有异议可直接推翻）

这三条是需求讨论时留下的开放项，用户未逐条指定，由 Agent 在已确认边界内收口；它们都影响数据或用户可见行为，因此显式列出而不是埋在实现里。

10. **条目归属单个分类**：分类是层级树，一个条目挂在**一个**分类节点上（可以为空 = 未分类）。不引入"一条目多分类"的关联表。
11. **关系类型的初始集合是两种**：`前置`（有向：A 是 B 的前置）与 `关联`（无向，存一条边按无向处理）。类型做成可扩展的枚举，将来加类型只是加取值。
12. **`apps/admin` 引入路由**（Hash 路由，与学习者端一致），因为要挂分类、条目、关系多个管理页面；不再用单屏内联。

### 用户增补（2026-10-10，批准后追加，需重新签署）

13. **补齐六项**：① 详情页的正文目录（锚点跳转）与上一篇／下一篇；② 管理员**草稿预览**（用学习者视角看未发布条目）；③ 附件的图注与点击放大；④ 学习者端分类树的完整展开／折叠与分类内筛选；⑤ **反向链接**（哪些条目的前置指向它）；⑥ **学习者自评掌握度**。

## 实现选择

以下由 Agent 在已确认边界内决定并记录理由；不是需要用户重新裁决的产品范围。

- **表名、模块名与界面文案使用「知识」而非「题库」**：用户描述的单元是知识内容而非有答案的考题，用「题库」会误导后续设计与使用者。
- **条目之间用一张独立的关系表**，而不是往条目表里塞父／子列：关系类型后续会增加，用边表比反复改主表便宜。
- **检索用 MySQL 的 `FULLTEXT ... WITH PARSER ngram`**：默认分词器不切中文，ngram 是 MySQL 社区版上唯一可行解；不足分词长度的查询退回 `LIKE`。**天花板**：ngram 索引对短查询无召回，且不做相关性调优。
- **图谱第一版只做「邻域视图」**：呈现当前条目与它的直接关联（手写 SVG，零新增依赖）。**全局力导向图推迟**——它需要图布局库，而本版的价值主要在"这条知识的前置与相关是什么"。这是对 REQ-003 的显式收窄，不是遗漏。
- **md 渲染使用 `react-markdown` + `remark-gfm`**：本项唯一新增的前端依赖。选它是因为它把 markdown 转成 React 元素而**不使用 `dangerouslySetInnerHTML`**，在构造上就避开了注入；用 `marked` + `dompurify` 需要自己保证消毒正确，多一个可错的环节。
- **文件带一条数据库记录，而不只是磁盘上的裸文件**：用一张表存 id（UUID）、原始文件名、内容类型、大小、上传者与时间。理由有二——读取时按 id 查表再拼路径，**从构造上排除路径穿越**；返回内容类型时用入库时**嗅探得到的类型**而不是客户端声明的。代价是多一张表与一次查询。
- **正文里存稳定标识而不是绝对地址**：md 中写 `/api/v1/knowledge/files/<uuid>`，渲染时由前端补上后端 baseUrl。因为桌面壳的来源是 `127.0.0.1:5310`、与后端不同源，绝对地址存死会两端失效。
- **删条目不删文件**：同一文件可能被多处引用；孤儿文件清理列为已知缺口，本版不做定时清理。
- **上传与附件只对管理员开放**：与内容录入同一权限，学习者侧不提供上传入口。

## 背景

WORK-001 定了架构骨架与契约，WORK-003 让平台第一次有了账号与身份。但平台**至今没有任何可读的内容**：学习者登录后无处可去，管理端也只有一个空屏。本项交付平台的第一批内容资产、第一条内容写入路径，以及第一处二进制资产的存取。

## 目标

让内容维护者能在管理端建立层级分类与知识条目、上传并引用附件、在条目之间建立关系、并在发布前以学习者视角预览；让学习者在学习者端浏览、按分类导航、检索并打开条目阅读（含渲染出的图片与附件），能把正文导航到具体章节、在条目之间前后移动，并对条目做一次自评标记作为个人学习状态的第一份记录。

## 非目标

- **不做练习、作答、判分与学习路径**；本版只引入**学习者自评**（懂了／还不懂）作为学习者模型的第一块砖，**不做任何基于作答的掌握度推断**。学习者侧也不再是纯只读（见「用户增补」第 14 条）。
- 不做 AI 相关的一切（精简、助手、Agent 运行时）——见文末拆分说明。
- 不做个人笔记与分享——见文末拆分说明。
- 不做向量检索与语义搜索。
- **不做云端对象存储**（S3／OSS／MinIO）：本版只用服务器本地文件，但存储收在端口之后以便将来替换。
- 不做音视频等大体积媒体，不做 PDF 之外的文档预览。
- 不做全局力导向关系图（本版只做邻域视图）。
- 不做富文本所见即所得编辑器（正文是 md，编辑用纯文本域 + 实时预览）。
- 不做内容的版本历史与回滚，不做孤儿文件的定时清理。
- 不做内容的多语言与国际化。
- 不做公开页 SEO（沿用既有决定）。

## 用户与工作流程

- **内容维护者（管理员）**：登录管理端 → 建／改层级分类 → 新建或编辑知识条目（标题 + md 正文 + 分类归属，先存草稿）→ **上传图片或 PDF 并把引用写进正文** → 建立条目之间的关系 → 切换到**草稿预览**确认学习者端看到的样子 → 发布。
- **学习者**：登录 → 打开知识库 → 按层级分类导航或关键词检索 → 打开条目阅读（md 渲染，含图片）→ 用正文目录跳到某个章节、用上一篇／下一篇继续 → 查看该条目的前置与相关条目（含反向链接）→ 对条目标记「懂了」或「还不懂」。
- **未登录访问**：页面一律导向登录页（沿用 WORK-003 的整体登录门）；**唯一的例外是文件读取端点**，见 REQ-007。

## 功能需求

- REQ-001 **知识条目实体**：必须有知识库表，一行一个条目，含标题、类 md 正文、分类归属、状态（草稿／已发布）与审计时间；用 Flyway 迁移建立，遵循既有主键、时间与命名约定。
- REQ-002 **层级分类树**：必须有可维护的层级分类，条目能归入分类，且学习者端能按树形结构导航。
- REQ-003 **条目关系与图谱**：条目之间必须能表达两种关系（前置、关联）；学习者端能只读查看某条目的前置与相关条目，并有一条从当前条目看出去的邻域视图。全局关系总览不在本版。
- REQ-004 **只读浏览**：学习者能列出条目、按分类树导航、打开单条查看，正文按 md 渲染（含其中的图片）；**未发布的条目对学习者不可见**。
- REQ-005 **检索**：能按关键词检索**已发布**条目并返回结果；检索必须能命中中文内容。
- REQ-006 **管理端内容录入**：管理员必须能在管理端创建与编辑分类、条目与关系，并发布条目；**该写入路径只对管理员开放，非管理员必须被拒**。
- REQ-007 **文件上传与引用**：管理员必须能上传图片与 PDF 附件并得到稳定引用，条目的 md 正文必须能引用它们且在学习者端正确显示。**存储必须收在一个可替换的端口之后**（本版实现为服务器本地目录）。**文件读取端点不要求登录**（用户裁决），因此文件名必须不可枚举，且必须从构造上排除路径穿越。
- REQ-008 **正文导航**：条目详情必须能从正文标题生成**目录并跳转到对应章节**，并提供**同分类内的上一篇／下一篇**；对某条目必须显式列出**哪些条目的前置指向它**（反向链接）。
- REQ-009 **附件呈现**：正文中的图片必须带**图注**（取图片的替代文本）且可**点击放大**；PDF 附件以链接形式提供。
- REQ-010 **分类导航交互**：学习者端分类树必须能**逐级展开／折叠**，并能**在分类内按名称筛选**。
- REQ-011 **草稿预览**：管理员必须能在发布前以**学习者视角**查看未发布条目（同样的 md 渲染、分类与关系）；该预览只对管理员开放。
- REQ-012 **学习者自评**：学习者必须能对条目标记**懂了／还不懂**、**按人持久化**、可取消；条目详情必须显示**自己的**标记；必须能列出自己标记过的条目。**他人的标记对本人永远不可见。**

## 质量要求

- **可测试性**：条目与分类的读写、检索、关系读取、管理端录入、角色拒绝、文件上传与读取，各有一条可本地重复执行的自动化检查。
- **授权**：管理端写入路径必须有自动化检查证明"学习者被拒、匿名被拒、管理员放行"三态；学习者侧只读接口必须有自动化检查证明看不到未发布条目。
- **上传安全**：只接受白名单类型（`image/png`、`image/jpeg`、`image/webp`、`image/gif`、`application/pdf`），单文件上限 10 MB；**MIME 嗅探与扩展名双重校验**并拒绝 SVG（可内嵌脚本）；存储类型以嗅探结果为准，返回时带上禁止内容嗅探的响应头；文件 id 为 UUID，不连续、不可枚举。
- **可诊断性**：迁移、录入、检索与文件上传的失败在服务端日志里可定位（哪张表、哪条记录、哪个文件 id），对外只返回稳定错误码。
- **前端一致性**：复用 WORK-002 的设计系统与令牌，颜色仍只有 `globals.css` 一个来源；新增的 `packages/knowledge` 含 `.tsx`，**必须同步登记 `@source`**（`source-coverage` 检查会拦）。
- **可访问性**：分类树可键盘导航；条目列表与详情有正确的标题层级与焦点状态；md 渲染出的代码块与表格可读，图片有替代文本，正文目录可键盘操作，放大后的图片可用 Esc 关闭。
- **用户数据隔离**：自评标记是本项目**第一条用户私有的业务数据**，必须有自动化检查证明**用户 A 读不到用户 B 的标记**；接口的归属判断只取自令牌身份，不接受客户端传入的用户标识。

- **depends_on WORK-002**：沿用设计系统、四个应用面（含 `apps/admin`）、边界检查。
- **depends_on WORK-003**：录入路径需要管理员角色，沿用账号、角色、登录门与前端令牌处理。

- **本项引入第一条用户私有的业务数据**（自评标记），落在 `paideia-knowledge` 内。当练习、作答与基于作答的掌握度成为独立子系统时，这张表很可能被取代或迁移——届时要走数据库迁移，而不是就地改名。
