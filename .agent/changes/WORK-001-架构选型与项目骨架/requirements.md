# 架构选型与项目骨架需求

## 已确认事实

- 仓库 `F:\Paideia` 当前为空，除 `.agent/` 生命周期工件外没有任何源码、构建文件或配置。
- 已联网核实（2026-10-09，详见 `.agent/references/architecture-landscape-2026.md`）：
  - Spring Boot 当前 4.1.1，JDK 基线 17、官方推荐 25；`spring-boot-starter-web` 已改名 `spring-boot-starter-webmvc`，Undertow 已移除，`@MockBean`/`@SpyBean` 已移除。
  - React 当前 19.3，不存在 React 20；React Compiler 1.0 已稳定。
  - MyBatis 当前 3.5.19，不存在 3.6.x GA。
  - JDK 25 虚拟线程钉住问题已由 JEP 491 修复；结构化并发仍是预览。
  - MySQL 社区版与企业版无法对 `VECTOR` 类型做原生距离排序（`DISTANCE()` 仅 HeatWave on OCI / MySQL AI 可用）。
  - AgentScope Java 稳定版 2.0.4（2026-10-08），2.0.0 GA 于 2026-07-10，Apache-2.0，有官方 Spring Boot starter 并对齐 Boot 4.0.1；其 RAG/embedding 能力未进入 v2 文档，可观测性仅有 OpenTelemetry 中间件，第三方生产案例未见公开证据。
  - Tauri 当前稳定版 2.12.1（v3 仍在 alpha）；Electron 当前 44.7.0。

## 用户决定

- 技术栈（2026-10-09 指定）：
  - 后端：Spring Boot 4 + JDK 25。
  - 数据访问：**手写 MyBatis，禁止引入 MyBatis-Plus**。
  - 数据库：仅 MySQL，不做多数据库适配（可使用 MySQL 专有语法与特性）。
  - 前端：React 最新稳定版。
- **不做多租户**：单一部署形态，不引入租户隔离维度。学习者账号与其个人数据之间的隔离仍然需要，但按普通授权问题处理，不引入租户架构。
- **本期不做向量化检索**：不引入向量库，不实现语义检索与 RAG；架构上必须留有接入位置。
- **前端必须一套代码同时交付 Web 与 Windows 桌面安装包**，最大化代码复用。
- **SEO 是后续需要，本期不实现**，但前端架构不得阻碍后续接入。
- **多数据库适配不做，完全放开 MySQL**（D-07）：仅考虑 MySQL，可使用其专有语法与特性（upsert、JSON 列与算子、`SKIP LOCKED`、全文检索、自增主键）。换库等于重写数据访问层，此为已知并接受的代价。
- **认证机制：自签 JWT，且必须可扩展**（D-10）：桌面端与 Web 同期交付，**会话 Cookie 因桌面壳来源非 http(s) 域被排除**。认证必须收在单一模块的端口之后，将来换 OIDC 等机制不改业务代码。
- **桌面版与 Web 同期交付，桌面壳用 Tauri**（D-12）。
- **消息与异步：引入 RabbitMQ**（D-14）：事件必须先写入 outbox（与业务数据同一事务），再由中继投递到 RabbitMQ，避免「数据库已提交但消息未发出」的双写丢失。
- **中间件与部署自托管在自有服务器**：RabbitMQ 等中间件与后续部署都放在自有服务器上；部署细节本期不考虑。服务器地址与凭据属敏感信息，一律不进仓库。
- **仓库为公开仓库**：凭据、密钥、令牌、私钥、连接串、服务器地址不得写入任何被 Git 跟踪的文件。
- **已裁决技术选型**（2026-10-09）：
  - D-01 整体架构形态：模块化单体。
  - D-02 模块边界强制手段：Spring Modulith。
  - D-03 后端构建工具：Maven。
  - D-04 仓库结构：单仓多模块（后端 Maven 多模块，前端 pnpm workspace 同仓）。
  - D-05 主键生成：数据库自增。
  - D-06 分页方案：MySQL 分页组件。
  - D-07 多数据库适配：不做，完全放开 MySQL。
  - D-08 数据库迁移工具：Flyway。
  - D-10 认证机制：自签 JWT（收在端口后保持可扩展）。
  - D-11 前端框架与渲染模式：Vite + React Router SPA。
  - D-12 桌面壳技术：Tauri，与 Web 同期交付。
  - D-13 前端数据层：服务端状态用 TanStack Query；客户端临时状态方案暂缓。
- **架构形态与全部技术选型由用户裁决**：Agent 只提供备选方案与优缺点，不代替用户做决定。业务模块的划分必须等需求明确后再进行。

## 背景

Paideia 要做「千人千面的 AI 个性化学习平台」，不是把同一套课程分发给所有人后只显示不同进度条。这要求学习者模型成为一等实体，内容与服务围绕单个学习者现场编排。仓库目前为空，架构形态一旦落地会约束之后所有工作项，因此必须在写业务代码之前定下来并留下可复审的依据。

叠加的要求是：同一套前端要同时跑在浏览器和 Windows 桌面上；登录后的应用与将来需要 SEO 的公开页要共存；后端要能在不重写业务代码的前提下换数据库。

## 目标

确定 Paideia 的整体架构形态与技术选型（由用户在完整备选与优缺点基础上裁决），并落地一个可运行、边界受自动化约束的项目骨架，使后续功能开发有稳定且可演化的地基。

## 非目标

- 不实现任何具体业务功能，也**不在需求明确前划分业务模块**。
- 不接入真实大模型生产流量；只做到架构就位与单点连通验证。
- 不实现多租户、组织/机构层级或按租户分库。
- 不引入向量库，不实现语义检索与 RAG。
- 不实现公开课程页与 SEO，只保证架构不阻断。
- 不实现离线写入与本地数据同步。
- 不做性能压测与容量规划。

## 功能需求

- REQ-001：必须建立一份完整的技术选项登记表，覆盖所有影响架构的决策点；每项列出备选方案、各自优点与缺点、影响面，且所有结论由用户裁决。
- REQ-002：架构必须承载平台的核心能力——每个学习者拥有独立的学习者模型（已掌握/未掌握的知识点、目标、当前进度），系统据此决定其下一步内容与练习。
- REQ-003：数据访问层以 MySQL 为唯一目标数据库，实现与验证均在 MySQL 上完成；分页、主键与 SQL 写法按用户裁决的方案执行。（原「多数据库可移植」要求已由用户于 2026-10-09 撤销。）
- REQ-004：必须交付可运行的端到端骨架：后端能构建并启动并提供至少一个接口；前端能启动并成功调用该接口展示真实返回数据。
- REQ-005：模块边界必须有构建期自动化检查，出现非法跨模块依赖时构建失败，而不是靠代码评审约定。
- REQ-006：必须保证用户之间的数据授权隔离：一次请求只能读到属于当前用户的数据，且有自动化检查防止越权读取。
- REQ-007：同一套前端代码库必须能构建出 Web 产物与 Windows 桌面安装包（Tauri），两端同期交付；业务代码不得直接依赖任何一侧的运行时 API，平台能力必须通过适配器接口隔离。
- REQ-008：前端架构必须允许后续为公开页面单独引入服务端渲染或静态生成，而不影响桌面端构建。

## 质量要求

- 可维护性：模块边界由工具在构建期强制；跨模块通信有单一入口，不出现散落的直接调用。
- 可演化性：将来拆分为独立服务或更换 AI 引擎时，不需要重写业务逻辑。
- 可测试性：边界约束、授权隔离、双端构建各有一条自动化检查，能在本地一条命令内复现。
- 可诊断性：关键运行配置（实际连接的数据库与版本、生效的模块结构）在启动时输出，便于排查环境差异。

## 约束与依赖

- 技术栈按「用户决定」执行，不再重新论证。
- 数据访问以 MySQL 为唯一目标，可使用其专有语法与特性；换库需重写数据访问层，不再保留可移植纪律。
- 依赖已安装的 `project-lifecycle` Skill 管理工件；本工作项须在需求获批后才能进入实现。
- 项目常驻规范 `.agent/rules/always.md` 尚为草案；确认前不得进入实现。

## 验收标准

- AC-001：技术选项登记表覆盖所有影响架构的决策点（不少于本文「待用户决定」列出的项），每项含备选、优点、缺点、影响面；全部结论由用户明确裁决并记录。
- AC-002：后端骨架在 JDK 25 上能构建并启动，健康检查端点返回 UP，且该结果有一次可复查的运行记录。
- AC-003：前端骨架能启动并成功调用后端接口，界面上展示的是接口真实返回的数据（不是硬编码）。
- AC-004：模块边界校验在构建流程中自动执行；人工引入一次非法跨模块依赖时构建失败，并留下这次验证记录。
- AC-005：至少一个仓储层用例在 MySQL 上通过，分页由 MySQL 分页组件产生并返回正确的总数与页大小。
- AC-006：存在自动化检查，能证明用户 A 的请求无法读到用户 B 的学习数据。
- AC-007：同一条构建命令能产出 Web 产物与 Windows 桌面安装包，且桌面版能启动并成功调用后端接口；存在自动化检查证明共享业务代码没有引用桌面壳专有 API。
- AC-008：公开页面的 SEO 接入路径在架构文档中写明并有最小可运行验证（例如一个预渲染的公开页面），且不影响桌面端构建。

### 数据与隐私待决定项

1. **角色模型**：只有学习者本人，还是存在教师、家长、管理员等可查看他人数据的角色。此项属于需求而非技术，但直接决定授权模型的数据结构，越早定越好。
2. **留存期限**：作答历史、学习行为记录、AI 对话记录各自保留多久，是否需要定期归档或清理。
3. **删除权**：学习者能否删除自己的数据；删除是物理删除还是标记删除；级联范围到哪里。
4. **未成年人合规**：若面向中小学生，涉及监护人同意、内容安全过滤，以及未成年人个人信息保护的额外要求。
5. **AI 对话数据处理**：对话是否留存、留存多久；发送给模型供应商前是否脱敏；供应商是否在境外（涉及数据出境）。此项与 D-09 绑定，建议在单独讨论 AI 时一并决定。
